# apps/www — fss.coody.app

Landing page for FSS. Headline: **"A Fast Security Scan for
developers."**

## Stack

Vite + React + TypeScript + Tailwind CSS 4 +
[shadcn/ui](https://ui.shadcn.com), following the Coody house style. The
build output (`dist/`) is uploaded to the Cloudflare **Pages** project
`coody-fss-www-prd-01` — there is no server-side code and no Pages Function,
only static assets. (`/install.sh` is the one exception: a zone Route hands
it to the `coody-fss-prd-01` Worker. See [deployment.md](deployment.md).)

Build-time integrations keep the CLI as the single source of truth:

- **Version badge** — `vite.config.ts` reads `FSS_VERSION` from
  `apps/cli/lib/common.sh` and injects it as
  `import.meta.env.VITE_FSS_VERSION`.
- **Installer** — the repo-root `install.sh` is copied into `dist/` at
  build time as a fallback copy; in production the Worker route answers
  `curl -fsSL https://fss.coody.app/install.sh | sh` first.
- **Sitemap** — `dist/sitemap.xml` is generated with `<lastmod>` set to the
  HEAD commit date.

## Agent readiness

The site is a single-page app, so anything an agent needs has to be a real
file at the site root — Pages' SPA fallback would otherwise answer
`/robots.txt` with `index.html` at `200 text/html`, which reads as "missing"
to every scanner.

| Path | Source | Purpose |
|---|---|---|
| `/robots.txt` | `public/robots.txt` | RFC 9309 groups, one per crawler. Explicit AI-crawler entries (GPTBot, ClaudeBot, Google-Extended, …), all `Allow: /`, each carrying `Content-Signal: ai-train=yes, search=yes, ai-input=yes`. Points at the sitemap. |
| `/sitemap.xml` | generated by `vite.config.ts` | One canonical URL; `<lastmod>` is the HEAD commit date, so it stays honest without maintenance. |
| `/llms.txt` | `public/llms.txt` | [llms.txt](https://llmstxt.org/) summary of the CLI — commands, exit codes, doc links. |
| `Link:` headers on `/` | `public/_headers` | RFC 8288: `canonical`, `describedby` → `/llms.txt`, `service-doc` → the repo, `license`. IANA-registered relations only. |

The `Content-Signal` line is repeated in every group on purpose: RFC 9309 says
a crawler obeys only the most specific group that matches it, so a signal in
the `User-agent: *` group alone would never reach GPTBot.

Two agent-readiness items live outside this repo — Markdown for Agents (a
Cloudflare zone setting) and DNS-AID (deliberately skipped). Both are covered
in [deployment.md](deployment.md#agent-readiness).

## Develop

```sh
pnpm install
pnpm --filter www dev        # local dev server
pnpm --filter www lint
pnpm --filter www typecheck
pnpm --filter www build      # tsc -b && vite build → dist/
```

## Deploy

Automatic on push to `main` touching `apps/www/**`, `install.sh`, or the
CLI version (see [deployment.md](deployment.md)), or manually from the
repo root:

```sh
pnpm build:www && pnpm deploy:www
```
